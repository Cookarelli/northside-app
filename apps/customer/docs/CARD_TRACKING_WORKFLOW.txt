TERMS — SUPPLIED BUSINESS DOCUMENTS ONLY
Owner/admin may configure an approved service-specific document with an immutable version, title, exact body and private approval reference. No real policy is supplied in this migration or source. When absent the UI reports that terms are not configured.
The authenticated customer accepts the current version for an owned card/service. The database records customer, service, version and server date, with a unique acceptance and serialized current-version checks. Revisiting the same version shows its original receipt; another customer cannot inherit it. Terms do not replace existing grading quote/exam decisions. Sample documents used in tests/browser fixtures are explicitly SAMPLE QA ONLY and are not approved Northside terms.

PRIVATE APIS AND PHOTOS
Browser cookie session: /api/private/card-tracking; native bearer: existing /api/mobile/v1/me/tracking/{service} and detail/photo routes, plus /me/tracking/terms. Existing route envelope/versioning is reused. The local /api/preview/card-tracking fixture route refuses production or non-loopback use.
Every list/detail/photo request verifies the existing actor, tenant and exact owner or independently approved grading claim. Grading claims do not grant consignment access. Customer responses use explicit schemas, exclude shared provider-order IDs and private staff fields, and fail closed on malformed requests. Legacy grading GETs reject conflicting or duplicate selectors before projection.
Attachments are delivered from authenticated no-store API responses; object keys and reusable signed Storage URLs are not returned to customers. Native photo bytes stay in memory with cache disabled and clear on account/lifecycle transitions. Valid image bytes are decoded, bounded, oriented and stripped of metadata; new files must match their private-storage readback hash and length before becoming ready. Existing stored originals are not rewritten. Generic attachment limit remains 5 MiB; the original exam/photo flow retains its separate 4 MiB limit. Existing PDF attachments remain supported.

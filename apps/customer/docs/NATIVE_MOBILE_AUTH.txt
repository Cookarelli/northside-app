SECURITY BOUNDARY
Provider identity maps through the existing tenant/shop/provider/subject UUID; no
email merge or parallel mobile customer identity is created. The mobile family
references a new dedicated Shopify customer-only ns.sessions parent. Its raw bearer
is AES-GCM sealed under a family-specific AAD and never sent to the app. Resolution
checks the parent hash, tenant/customer/provider/no-staff/expiry/revocation, current
origin+variant allowlist, and unchanged ns.context/RLS. Escrow is wiped on revocation.
DB+encryption-key compromise can expose the dedicated parent, just as existing
provider-token escrow can be decrypted with that key; keep restricted roles and key
storage separate. Maximum parent lifetime is eight hours without extension.
Renewal replay returns a sentinel so revocation commits before the API error is
thrown. Logout may use a spent renewal to revoke a concurrently rotated family.

Order history is fetched from Shopify Customer Account API through the current
server-held provider token and existing customerAccount query, then immutable
bindCustomer mapping, then a narrow schema projection. No Admin order feed,
operational ledger, email filter or invented fallback is presented as real history.
Customer-service reads use unchanged customer-only withSession and owner/tenant RLS,
with only id/kind/title/status fields projected. Staff notes, addresses, photos,
provider tokens, costs, pooled totals and staff authority are not exposed.

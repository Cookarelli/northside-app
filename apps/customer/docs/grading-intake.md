# Digital grading: procedure, verification and recovery

Verified September 16, 2026. **Implemented and verified locally; not deployed by this work and awaiting live configuration.** Local browser identities, cards, fees, shipping references, photographs and results are clearly labeled SAMPLE. The application uses the existing Shopify customer identity and invited staff identity; it does not create an alternative live customer account system.

Open [staff intake](http://127.0.0.1:3000/staff/grading), [staff operations](http://127.0.0.1:3000/staff/grading/operations), or [customer grading](http://127.0.0.1:3000/my-cards/grading). The prepared website entry is `/grading`. The actual public website is Square Online/Weebly; connecting its live navigation remains deferred by the user. No public portal domain is assumed.

## Staff procedure

1. **Identify the collector and save the physical intake first.** Select the exact verified customer or create an unclaimed receipt contact. Never identify ownership by email alone. Enter the card description, set/number/parallel and number of physical cards. Each copy receives a distinct permanent ID even when every descriptive field is identical. At the existing $5 examination rate, three cards have a $15 examination subtotal. This is a received-card receipt, not proof of payment. Each intake preserves its rate snapshot; later rate changes cannot rewrite it.
2. **Confirm photography on each saved card.** Use Take photo on a phone/tablet, or Choose file on any supported browser. Required: front and back. Optional: condition closeups and an existing paper exam photo. A camera input requests the rear camera, but the actual picker depends on the device/browser. Accept JPEG, PNG and single-frame WebP, at most 4 MiB and 24 megapixels. HEIC/HEIF, RAW, GIF, PDF, SVG and animated images need supported export. The server decodes, applies EXIF orientation and removes location metadata. Inspect the preview, retake if needed, upload, and wait for **Confirmed in private storage**. Preview and 100% transfer are not storage confirmation. **Photos missing** stays until the required sides are confirmed.
3. **Enter the Northside Exam.** Centering, Surface, Edges and Corners start blank and require integer scores 1–10. Write customer-visible Notes, manually enter Projected grade or choose Unable to estimate, and use the separate Internal staff notes field. Zoom photos alongside the assessment. No grade is inferred from photos or calculated from the four scores.
4. **Save draft, then publish explicitly.** Draft fields/internal notes remain private. Publication requires saved front/back images with verified storage, all four scores, an estimate choice, authenticated examiner signoff and a reason. The server records examiner and timestamp. Corrections produce a new signed revision with an actor/reason; older reports and photograph snapshots remain unchanged. Print the selected published report for customer photos, scores, public findings, estimate and signature; internal notes, correction reasons and paper-exam images are excluded.
5. **Configure the quote and obtain a decision.** Set confirmed provider/service and itemize external grading, allocated shipping, insurance and other charges. Unknown amounts stay unset and display Not yet quoted / Total pending, never free. A configured zero is different from blank. PSA is confirmed. BGP remains unconfirmed/internal and is not renamed BGS. The collector approves selected cards against exact card IDs, exam revisions, provider/service and quote revisions. Any changed quote/published exam needs renewed approval before dispatch.
6. **Scan and dispatch.** Use Staff grading operations to create a batch, submission reference, carrier and tracking. Scan each Northside card label; mixed collectors retain separate ownership. The server checks current approval, physical Ready to submit state, matching service and no other active outbound assignment. At the explicit carrier handoff, it rechecks every card and preserves the exact manifest/approval evidence transactionally. A label identifies a card; it never authorizes release. Later tracking edits cannot rewrite the dispatched manifest.
7. **Record only evidenced milestones and returns.** Received → Examination in progress → Awaiting customer decision → Ready to submit → Sent to grader → Grader received → Grading in progress → Returned to Northside → Ready for pickup → Completed. Holds/exceptions retain physical custody. Do not invent missing grader events or advance with a timer. Return/cancellation before dispatch removes the draft assignment; post-dispatch withdrawal requires staff review. On partial return, update only cards physically received, with actual grade or no-grade outcome and certificate if available. Upload separate returned front/back images before readiness/release. External results never overwrite the Northside estimate.
8. **Verify and acknowledge pickup.** Scan every card being handed over. Independently verify the collector or named representative against the collector record; for representatives, also record independently verified authorization. Do not store ID-document numbers/photos. Obtain recipient acknowledgment of the exact list and save with staff identity/time/reason. Only those cards become Completed. A QR, email or typed name alone is insufficient; duplicate release is blocked. This grading workflow is separate from disabled future retail order pickup.
9. **Preserve payment and import evidence.** Link only a verified reconciled Shopify order belonging to the correct collector/approved claim, or label actual external payment source/reference/date/amount as staff recorded. A reference creates no transaction. For intake/status CSV, map columns, use stable source/external row IDs, save and review validation, then explicitly commit. Repeated identical rows skip, conflicting row reuse fails and stale card versions require a new review. CSV cannot approve, dispatch or complete pickup. Review notification failures/UNSENT jobs in operations/Engagement; do not resend an operational action to retry a message.

For detailed controls see [Northside Exam](NORTHSIDE-EXAM.md), [customer grading](CUSTOMER-GRADING.md), and [staff operations](STAFF-GRADING-OPERATIONS.md). One external submission cycle is preserved per intake-card record; the current workflow does not recycle dispatched manifests for re-submission.

## Customer flow

1. Sign in with the existing Shopify customer account. The grading/card/exam destination is retained through login. The browser and installed app use the same responsive portal and underlying records.
2. Under **My Cards → Grading**, view only owned or independently approved receipt-claim records: drop-off photos, intake receipt, published exam/reports, itemized quote, current status/timeline/last update and recorded final result. Draft exams, paper exam images, staff notes, verification evidence and pooled manifests are private.
3. Select the exact cards to approve for external grading or request return before dispatch. The confirmation lists the current exam/quote revisions and provider/service. Renew approval when material evidence changes. After an uncertain response, retry the same saved request or inspect latest records before choosing again.
4. After dispatch, a withdrawal request asks staff to review; it does not cancel a shipment or prove physical return. Pickup notifications lead back to the owned card. Northside's original estimate remains separate from any final external result.
5. For an unclaimed intake, submit the private receipt claim code after sign-in. The code alone does not grant access: staff independently verifies receipt and identity and approves that case only. Email, an intake number or possession of a QR does not establish ownership.

## Recovery steps

| Situation | Safe action |
| --- | --- |
| Intake response uncertain | Inspect the saved receipt/card list and retry the original request. Three physical copies should still be three IDs with one intake subtotal. Never make a second intake to repair a photograph. |
| Upload fails before storage | Keep the received card. Retry the same photo on that card. After refresh, reselect the same file; its hash resumes the existing pending attempt. Other completed photos remain saved. |
| File stored but acknowledgment lost | Retry the same request/file. The server confirms existing stored bytes and returns the original photo identity. Do not treat the browser preview as success. |
| Unsupported/large file | Export JPEG/PNG/WebP within 4 MiB and 24 megapixels. Keep the record and retry with a supported file. Never rename HEIC to JPEG without conversion. |
| Confirmed photo unavailable/corrupt | Inspect private storage and restore the exact bytes/reference from the paired backup. Publication/readiness/release must remain blocked until bytes verify. Do not toggle ready flags manually. |
| Unsaved or stale exam | Save the draft explicitly. If another update wins, reload the current version and review before saving again. A published correction requires a new revision/signoff/reason, never overwriting history. |
| Quote/approval/dispatch conflict | Reload current state. A committed quote/exam change or withdrawn approval blocks waiting dispatch. If dispatch committed first, a later quote or pre-dispatch return is rejected; use the post-dispatch staff-review path. Never change status to bypass current approval. |
| Uncertain dispatch or pickup response | Retry the same exact request; preserved manifest/release identity resolves once. Inspect saved state before changing selection. Do not create another batch or release to “make sure.” |
| CSV duplicate/conflict/stale review | Exact previously applied rows skip. Resolve changed external-ID reuse or generate a new reviewed event ID. If the card changed since preview, make a fresh review. Preserve the old mapping/audit. |
| Email/provider failure | Inspect the original durable job, attempts and error. Let the bounded worker retry the original key after backoff. Do not repeat a grading event, dispatch or pickup. Review uncertain provider acceptance before replay; no real tests were sent here. |
| Restart or backup/restore | Stop the preview cleanly; preserve both `work/grading-preview/` and `work/grading-photos/`. Never open one database directory from two processes. Hosted recovery requires coordinated database/private-object backups, immutable revisions/manifests/approvals/releases and jobs, followed by isolated verification and reconciliation. See [backup runbook](BACKUP-RESTORE.md). |
